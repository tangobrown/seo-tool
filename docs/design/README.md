# Handoff: SEO Autopilot — Agency Dashboard

## Overview
An internal tool for an SEO agency to manage clients of an automated SEO product. For each client the operator can:
- **Review recommendations** generated by automated site scans, and approve, defer or decline them in batches. **Approving triggers Claude Code to implement the changes** on the client's site.
- **View reports**: top-level search analytics, plus a **monthly report auto-generated on the 1st** summarising the previous month. The report can be copied as plain text into a client email.
- **Configure the client**: their tier (which drives blog-post frequency and scan cadence), contact details, target keywords and automation toggles.

A workspace-level **Settings** area holds general settings, tier definitions, integrations and notifications.

The guiding principle is **simplicity**: a calm, document-like UI (minimal chrome, warm greys, hairline dividers, no heavy cards).

## About the Design Files
The files in this bundle are **design references created in HTML**. They are prototypes that show the intended look and behaviour, not production code to copy directly. Recreate them in the target codebase's existing environment (React, Vue, etc.) using its established patterns and libraries. If there is no codebase yet, pick an appropriate stack; Next.js + React + Tailwind + Postgres is a sensible default.

To view the prototype, open `SEO Autopilot.dc.html` in a browser, with `support.js` in the same folder. All data in it is mocked in-memory.

## Interactions & Behaviour Summary
- **Navigation**: sidebar, breadcrumbs and table rows. Switching client or tab clears the selection. Opening a client always lands on Recommendations.
- **Batch actions**: these are the core behaviour.
  - Approve, Defer and Decline apply to the whole selection, then show a toast with Undo.
  - **Approve must enqueue one Claude Code job per batch** containing all selected recommendations for that client.
  - Undo should be honoured only before the job starts. After that, offer cancel/revert via the job status instead.
- **Autosave**: all settings inputs save on change (debounce about 500ms). There are no Save buttons.
- **No animations** in the mock. If you add any, keep transitions subtle (150ms ease on background and colour).
- **Responsive**: content is fluid below 920px; the sidebar stays fixed at 240px. Add a collapsible sidebar below about 768px.

## State / Data Model (suggested)
```ts
Workspace { name, senderName, replyTo, signoff, notifications: { newRecs, report, weekly } }
Tier { name: 'Starter'|'Growth'|'Pro', postsPerMonth: number, scanFrequency: 'Monthly'|'Fortnightly'|'Weekly', price: string }
Client { id, name, domain, tier, contactName, contactEmail, industry, location, cms,
         keywords: string[], autoApproveLowImpact: bool, reviewBlogPosts: bool, includeInMonthlyReport: bool,
         archivedAt?: Date, createdAt }
Recommendation { id, clientId, category: 'Technical'|'On-page'|'Content'|'Links', impact: 'High'|'Medium'|'Low',
                 title, description, targetUrl, status: 'pending'|'approved'|'deferred'|'declined',
                 actionedAt?, actionedBy?, batchId? }
Batch { id, clientId, recommendationIds[], status: 'queued'|'running'|'done'|'failed', createdAt }   // Claude Code job
MonthlyReport { id, clientId, period: 'YYYY-MM', generatedAt, summary, sections: {title, items[]}[], readAt? }
Integration { key, connected, config }
```
**Background jobs:**
- **Site scan** at the tier cadence. It creates pending Recommendations; low-impact technical fixes are auto-approved if the client toggle is on.
- **Blog generation** at the tier cadence. Drafts land in Recommendations as `Content` items if "Review blog posts" is on.
- **Monthly report** on the 1st at 07:00 (workspace timezone). It summarises approved and implemented work plus GSC/GA4 metrics for the previous month.
- **Analytics sync** from GSC/GA4 (shows as "Synced … ago" in the top bar).
